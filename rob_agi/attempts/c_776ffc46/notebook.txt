Challenge 776ffc46: Transform blue plus shapes in a grid

Key observations:
1. Only blue plus shapes (5 pixels in a + configuration) are transformed.
2. The target color for transformation is determined by the color most frequently adjacent to or enclosed by gray borders.
3. Gray (5) acts as a border and is not part of any region to be transformed.
4. All transformations are applied simultaneously.

Rules:
1. Find the target color by counting occurrences of red (2) and green (3) adjacent to all gray borders collectively.
2. Choose the color with the higher count as the target color.
3. If counts are equal, use red as the target color.
4. Identify all blue plus shapes in the grid.
5. Transform these blue plus shapes to the target color.
6. Other blue shapes and colors remain unchanged.

Things that don't work:
- Transforming all blue regions of any shape.
- Using only the first encountered color as the target color.
- Checking only for colors enclosed within gray borders.
- Considering only orthogonally adjacent cells when counting colors near gray borders.
- Returning the input grid unchanged when a target color is found but no blue plus shapes exist.

Lessons learned:
1. The target color determination must consider all gray borders in the grid collectively.
2. Counting occurrences of red and green must include diagonally adjacent cells to gray borders.
3. The transformation of blue plus shapes is working correctly, but the target color identification was the main issue.
4. The function should only return the input grid unchanged if no red or green color is found adjacent to any gray border.
5. Using a set to store unique adjacent cells prevents double-counting when gray borders are adjacent to each other.

Next steps:
1. Modify the method for counting red and green occurrences to consider all 8 adjacent cells (including diagonals) for each gray border cell.
2. Ensure that the counting is done collectively for all gray borders, not individually.
3. Implement the correct tiebreaker rule: use red if counts are equal.
4. Verify that blue plus shapes are correctly identified and transformed.
5. Add a condition to return the input grid unchanged only if both red and green counts are zero.

Unknowns:
- Whether there are any edge cases where the current implementation might fail (e.g., complex arrangements of gray borders).
- If the order of processing cells in the grid affects the outcome in any way.
